# 第 4 階段：完整業務備份與大量資料讀取
日期：2026-09-12

## 範圍
家庭工具匯出目前家庭空間的 30 張業務資料表；值班工具匯出目前登入使用者的 10 張業務資料表。實際清單以 src/lib/backup-format.ts 的 BACKUP_TABLES 為準，新增表需同步更新 SQL、清單與測試。

家庭備份補齊待購清單、比價來源、投資帳戶、股票、交易、股利、股權異動；保留已封存業務資料與子表。值班備份涵蓋設定、值班及時段、請假及逐日紀錄、餘額流水、匯入批次與原始列、班別覆寫。沒有刪除原本投資模組的專用匯出。

不修改交易／FIFO／股利／減資、記帳／拆帳或休假餘額計算公式。不修改正式業務資料，不提供正式資料庫的一鍵覆寫。

## 格式與安全
- JSON version 2，含匯出時間、範圍 ID、精確表清單、各表筆數、各表 SHA-256。
- 數字型資料庫欄位以十進位字串保存；還原須依原欄位型別轉換，避免 JavaScript 精度損失。JSON 內嵌資料仍維持原 JSON 格式。
- 單一 STABLE、SECURITY INVOKER RPC 取得一致的資料庫敘述快照，沿用 RLS；匿名不能執行。家庭另驗證空間成員；值班只讀本人資料。
- SHA-256 是毀損檢查，不是數位簽章或加密。檔案含私人資料，需由使用者妥善／加密保管。
- 不包含 Auth 密碼、登入 session、金鑰、平台設定、外部附件／連結實體檔。不能取代第 1 階段的平台災難復原材料。
- 舊版檔案不刪除，但不保證補足當時未匯出的模組。不可把舊版直接當 version 2 還原。

## 大量資料與失敗處理
- 線上匯出資料庫結果上限 20 MiB、封裝及瀏覽器驗證上限 32 MiB；超限明確失敗，不回傳截斷檔案。較大資料需管理員隔離備份流程。
- HTTP 回應分塊串流；瀏覽器驗證版本、範圍、資料表、ID、筆數與 checksum 後才交付下載。成功文案只表示已交由瀏覽器，不宣稱檔案已存入磁碟。
- 完整讀取路徑每頁 500 筆，檢查精確總數、重複 ID、讀取中筆數改變；超過 100,000 筆明確失敗。一般畫面分頁不是跨頁交易快照，並行編輯但筆數未變仍需重新整理。
- 家庭：投資、帳單、記帳、拆帳對帳、待購與來源；值班：月資料及累計餘額依賴資料。既有刻意限制「最近 N 筆」的畫面不擴大範圍，完整備份不受其限制。

## 驗收
- 家庭 132 項測試通過；值班 67 項 Vitest + 15 項 Auth 測試通過。TypeScript 檢查通過。
- 兩套隔離 production build 通過，桌面與 390px 手機備份頁可操作。
- 隔離資料：家庭 6,001 筆交易；值班 6,003 筆流水，無 1,000／5,000 筆截斷。
- 全部表匯出後以原型別還原到獨立測試 schema；雙向 EXCEPT ALL 與業務表外鍵驗證通過。部分表為空表，非每個模組都有非空 fixture。
- 匿名拒絕、不同帳戶隔離、校驗碼毀損／版本不符／重複 ID／分頁異動測試。家庭瀏覽器另驗證故障提示與恢復下載。
- 測試僅使用新建立的假資料與帳號，測試後撤銷 session 並清除。正式資料不做還原測試。

## 隔離還原流程（管理員）
1. 保留原檔唯讀副本；驗證 format/version/scope、表清單、ID、counts、checksums。校驗失敗立即停止。
2. 建立無正式憑證的獨立測試環境，先套用該版資料庫 migrations；確認目標不是正式 project。
3. 先處理 Auth 身分對應，或使用測試 schema 驗證純業務資料。不得拿正式登入憑證灌入測試。
4. 使用 jsonb_populate_recordset 將 decimal 字串按原型別寫入；依外鍵相依次序建立，或在交易內完成並檢查外鍵。
5. 比對每表筆數、雙向內容差異、父子關係及主要畫面／計算；沒有通過不得切換。
6. 本階段沒有授權任何正式資料覆蓋步驟；實際災難復原仍需明確選定備份與目標。
7. 撤銷測試帳號／session、移除假資料，保留不含私人資料的驗證報告。

## 發布與回退
新增的兩個唯讀函式為加法 migration。先驗證資料指紋，再套用函式、建置候選部署、驗證未登入存取，最後提升正式網域。
若發現回歸，將正式網域指回前一個部署；新函式可保留，不必為了回退刪改任何業務資料。
