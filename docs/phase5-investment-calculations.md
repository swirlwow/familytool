# 第 5 階段：投資計算與報價可追溯性

## 範圍與保持不變

僅調整投資模組。成本維持移動加權平均，原始買賣、股利、減資及家庭帳務資料均不改寫。值班工具不修改。

## 計算口徑

- 市值＝持股數 × 股價；預估賣出淨值＝市值 − 預估手續費 − 預估交易稅。
- 未實現損益＝預估賣出淨值 − 持有成本。
- 現持股累計除息依 FIFO 批次追蹤，只含目前仍持有批次參與的現金除息毛額。
- 減資保留該批次歷史除息總額，之後實際賣出才按 FIFO 移除；配股新增股數，不重複新增現金股利。
- 除息後成本＝持有成本 − 現持股累計除息。含股利損益＝預估淨值 − 除息後成本。
- 歷年實收股利是另一口徑，含已賣出批次，並扣除匯費等；不得與累計除息混用。
- 減資仍使用明確填寫的 cost_adjustment，不擅自把 cash_return 當作成本調整。

## 可見差異

1. 修正 TPEx / TPEX 大小寫導致上櫃費稅未估算。一般費稅公式不變；折扣、最低費用、當沖、免稅特殊商品仍須以券商為準。
2. 持股可展開「計算明細／對帳」，查看公式、各批次參與除息、減資及結算差額提示。對帳輸入只存在畫面，不寫資料庫。
3. 每筆報價保留來源與時間，區分最近成交、買一參考、收盤、手動及來源未記錄；標示非今日報價。不是串流行情，也不保證無延遲。
4. 選取日期較新的有效來源；資料庫原子更新防止較舊日期／時間覆蓋新報價。同日已存時間戳時，不接受無時間戳報價覆蓋。

## 驗收

- 143 項單元測試、TypeScript 與 scoped ESLint 通過。
- 隔離 production build 通過；桌面／手機計算與對帳、重新整理報價標示已驗證。
- 獨立 Supabase 驗證匿名／跨 workspace 拒絕、並行更新保留新報價、未來日期拒絕、30 表 6000 筆以上備份還原及測試帳號清除。
- 正式 30 表原有欄位在新增 migration 前後逐表雜湊相同。

## 限制

尚不能宣稱每個券商數字完全一致：需同一日期／價格、費率折扣、除息口徑與完整原始資料。實收與成交金額加減費稅不同、減資成本調整為 0 等情況僅提示，不替使用者改原始紀錄。
