# 資料讀取回歸檢查（2026-09-12）

## 問題與修正

拆帳的三個 repository 查詢，在加入分頁後以 `from/to` 作為頁碼參數，遮蔽了外層日期。因此日期欄位收到 `0/499` 等數值，造成 API 讀取失敗。

修正 `getSplitsInRange`、`getSettledItemsForUI`、`getSettlementHeadersThroughDate`：分頁改用 `pageFrom/pageTo`，日期仍使用原輸入。保留工作區篩選、排序、資料完整性檢查及原計算方式。

## 驗證範圍

- 所有 `readAllPages` 呼叫與其他 range/limit 查詢的靜態檢查。
- 全套 150 項單元測試通過，含新增 6 項日期／跨頁／空資料回歸測試。
- 全專案 TypeScript、ESLint error 檢查及隔離 production build 通過。
- 本機獨立 Supabase、暫時測試帳號下完成 21 項已登入 API 檢查：拆帳及日期邊界、記帳、結清紀錄、對帳、帳單、股票及匯出、待購、記事、便利貼、行事曆及訂閱、基本資料、完整備份。
- 501 筆測試拆帳跨越兩頁：總額 5,010、已結清 10、剩餘 5,000；截止日前尚未結清時為 0；空日期區間無拆帳。
- 瀏覽器確認拆帳頁顯示上述數字且無讀取失敗；股票測試資料亦正常載入。

- 18 個主要頁面／舊網址巡查通過；記事導向行事曆、舊拆帳設定導向拆帳均符合既有程式。

## 限制與資料保護

本次不是所有可能輸入與第三方服務狀態的窮盡證明。正式站舊日誌另有一筆股票讀取失敗，隔離 API 與畫面均未重現；舊錯誤訊息未保留底層原因，不能據此宣稱該筆問題已修復。

不修改正式資料、權限、資料庫結構或登入設定；只在確認空白的獨立測試資料庫建立合成資料。驗證腳本、建置紀錄及頁面證據保留於專案外的本機 `read-audit-2026-09-12` 資料夾，不上傳測試帳號或憑證。
