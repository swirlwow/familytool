# FAMILYTOOL 介面驗收（2026-09-01）

這次只修復現有介面，不新增延伸功能，不修改帳務計算、正式資料或資料庫結構。

最終結果：38 項單元測試、75 組尺寸／空資料檢查、12 項互動檢查通過；ESLint 與正式建置通過。
另以截圖檢視首頁、手機記帳／付款視窗／分類／拆帳、平板行事曆與桌機便條紙內容。

- 行事曆：手機與平板都以底部導覽的同一個斷點計算高度。
- 記帳、付款、帳單金額、固定帳單、行事曆：共用 Radix 彈窗，支援焦點限制、Escape、關閉後回到原按鈕。保留原本提交邏輯。
- 彈窗與確認窗：使用可視視窗高度、保留邊距、可捲動；長表單操作列固定在彈窗底部。
- 統一分頁、主要新增按鈕、鍵盤焦點、提示樣式與手機觸控高度。
- 修正長名稱、大金額溢出；手機拆帳明細保留全部欄位，改成標籤與內容相鄰排列。
- 補付款人管理次要入口；手機「更多」可用鍵盤操作；點選導覽後收起側欄。
- 備份顯示準備中、錯誤與交由瀏覽器下載的提示，不把登入頁或錯誤回應存成備份。
- 中文輸入法組字期間按 Enter 不會誤送出共用文字輸入視窗。

## 驗收方式與限制

使用真實頁面元件與 CSS，但以獨立 Vite 測試入口替代 Next 路由及登入。
測試伺服器只綁定 `127.0.0.1:4179`，不讀取 `.env.local`，所有 API 使用假資料，非 GET 操作回傳 409，完全不接正式資料庫。

`check.ps1` 檢查 15 個頁面，寬度 320、390、768、1440，加上 390 的空資料情境，共 75 組。
每组等待 main 載入，確認沒有頁面水平溢出或腳本錯誤。長名稱與大金額是假資料壓力情境，不是使用者帳務。
機器結果輸出到已忽略的 `.local-verification/responsive-results.json`。

頁面：首頁、記帳、財務儀表板、帳單、拆帳、結清紀錄、行事曆、便條紙、便條紙內容、分類、付款方式、店家、付款人、備份、登入。

`interactions.ps1` 驗證付款/帳單編輯/記帳編輯/行事曆彈窗、Tab/Shift+Tab、Escape、焦點復原、390×420 短視窗、平板日曆與桌機便條紙入口。
入口測試先 focus 再觸發實際按鈕 handler；Tab 與 Escape 使用瀏覽器鍵盤事件。沒有測試付款或儲存到真實 API。

**這不是實體手機驗收。** 尚待 iOS Safari / Android Chrome 軟鍵盤、觸控拖曳、正式登入後完整 CRUD 與 SSO 同意畫面驗收。
正式建置與原有帳務單元測試另外執行；假資料預覽不取代 Next.js 正式執行環境的驗收。

## 重跑

1. `npm ci`
2. `node tests/ui/server.mjs`
3. 安裝／定位 `agent-browser`，Windows 建議直接使用其 `bin/agent-browser-win32-x64.exe`，避免批次檔改寫 JavaScript 引號。
4. `./tests/ui/check.ps1 -AgentBrowser "完整執行檔路徑"`
5. `./tests/ui/interactions.ps1 -AgentBrowser "完整執行檔路徑"`
6. `npm test`、`npm run lint`、`npm run build`

完成後關閉 `family-ui`、`family-inspect` 隔離瀏覽器，停止本機測試伺服器。

## 仍需實機與正式登入驗收

- 手機鍵盤開啟後，日期、金額、店家、內容及確認按鈕都可捲到、可點選；關閉鍵盤後底部導覽復原。
- 分類／付款方式的觸控拖曳、長名稱編輯與同列啟停刪除。
- 正式登入後，以可清理的測試資料確認新增、修改、取消、刪除、結清與復原；不要以真實帳務做測試。
- 正式備份下載、CSV 匯出與 SSO。本紀錄為部署前驗收結果；部署狀態以 Vercel 紀錄為準。驗收未寫入任何正式資料。
